# AstraDB 文档库（docs）

> 文档按性质分为四个板块：`design/`（设计）、`review/`（评审）、`phaseReport/`（阶段报告）、`test/`（测试）。
> 约定：**新文档默认在 `design/` 编写**，仅在内容明显属于评审、阶段报告或测试时才写入对应板块。

## 板块结构

| 板块 | 定位 | 内容 |
| --- | --- | --- |
| [`design/`](./design/) | **设计类文档（主要编写区）** | 场景、总体设计、客户端设计、优化提案 |
| [`review/`](./review/) | 评审报告 | 总体现状评价与 P0 专项评审（review-p0.md） |
| [`phaseReport/`](./phaseReport/) | 阶段交付报告 | 阶段交付核对报告（phase-report.md） |
| [`test/`](./test/) | 测试文档 | 测试计划/用例/报告、缺陷跟踪（defects.md） |

## design/ 文件清单

- `design.md` — 总体设计文档（核心，版本/状态见文首）
- `scenario.md` — 场景文档（要解决的问题与适用场景）
- `client-design.md` — 客户端设计与二进制数据流协议
- `optimization.md` — 评价与优化方案（各优化项标注状态：候选 / 已实施；问题清单 G-01~G-11 见 review/）

## review/ 文件清单

- `review-p0.md` — 总体现状评价与 P0 可靠性优化评审报告（第 1 章总体问题清单 G-01~G-11，第 2 章起 P0 专项评审；v1.2 复审通过）
- `review.md` — 全项目评审报告（core/server/client 问题清单、测试覆盖与文档一致性核对、修复建议优先级）

## 编写约定

- 新增设计类文档一律放入 `design/`，并更新本 README 的文件清单；
- 文档间相互引用使用**相对路径链接**（移动文件后需同步修正）；
- 状态标记统一放在文首引用块（版本 / 状态 / 日期 / 关联文档）。
