## 2. 里程碑

### M9 · 存储格式演进（FORMAT_VERSION 2 → 3）—— 下一个优先窗口

- **目标**：合并完成三项涉及格式版本变更的优化，避免多次"旧数据需重导"：
  - **O-04 点字典去字符串化**：INT/LONG 主键改原始类型键路径（primitive 开放寻址哈希），百万点内存降一个数量级；
  - **O-05 Gorilla 分块 checkpoint**：列内每 1024 行存 checkpoint，`valueAt`/`decodeRange` 从 checkpoint 起跳，单点历史查询提速 ≥ 3 倍；
  - **O-16 schema 演进预留（追加列）**：schema v2 允许表尾追加可空列，旧段缺列视为全 null。
- **验收**：valueAt/decodeRange 与整列解码一致（属性测试）；单点历史查询 20 万行快照提速 ≥ 3 倍；百万点内存降一个数量级；旧段 + 新 schema 混合读取正确；全量 70 项回归不回归。
- **依赖**：三者在同一次 FORMAT_VERSION 升级中实施；冻结格式后补充"版本迁移工具"（旧段重导脚本）。
- **状态**：`未开始`

### M10 · 内存与性能

- **O-06 导入/查询内存峰值回落**：编码后释放原始列缓冲、`fullSnapshot` 改迭代式输出、查询行值原始类型数组——百万行内存峰值降 ≥ 40%，向"2~4 快照 ≤ 100MB"约束收敛；
- **O-07 写入 fsync 策略可配**：`immediate`（默认）/ `batch-window` / `none` 三模式，吞吐与崩溃窗口由用户取舍。
- **状态**：`未开始`

### M11 · 查询能力

- **O-08 统一"精确 / 最近一次 ≤ ts"查询语义**：`getSnapshot` 增 `LATEST` 模式，同时对齐 README 注释（G-09 遗留漂移）；
- **O-09 快照 diff 查询**：按 pointId 归并比较输出新增/删除/变更三组（与 O-11 共用解码路径，可合并实施）；
- **O-11 粗粒度流式聚合**：count/sum/avg/min/max 解码循环内累加，近零额外内存。
- **状态**：`未开始`

### M12 · 生态与运维

- **O-10 段导出工具（CSV/Parquet）**：打破专有格式锁定，导出可重新导入（roundtrip）；
- **O-12 分片粒度可配（小时/天/周）**：回填/删除成本与粒度成反比；
- **O-13 metrics 端点**：Prometheus 文本格式，表级行数/段数/缓存命中率/慢查询/导入时延；
- **O-14 安全加固（剩余）**：TLS 部署说明、请求限流（BCrypt 口令已于 R-02 落地）；
- **O-15 CI 与文档卫生（剩余）**：GitHub Actions、surefire perf 测试分离（文档同步已于 2026-08-21 落地）。
- **状态**：`未开始`

### 工程卫生（随行，不单独设里程碑）

- 黑盒工程 `test/`（31 项）纳入 CI；
- 性能黑盒断言（scenario 约束：写入 ≤5s / 读取 ≤2s）；
- review.md 观察项逐项评估：core O-1~O-16（O-14 已随 SF-4 缓解）、server/client SO-1~SO-3/SO-5~SO-13（SO-4/SO-7 已部分缓解）。

## 4. 风险与依赖

1. **格式升级窗口**：当前存储格式仅 v2、schema-registry 仅 v1，是格式演进的最后低成本窗口；O-04/O-05/O-16 必须合并为一次 FORMAT_VERSION 升级（3），并同步"版本迁移工具"，此后冻结格式；
2. **O-07 与 O-01 交互**：fsync 策略与已归档的批量导入原子化（staging）存在交互，设计时需一并考虑崩溃语义；
3. **Docker 未实测**（环境无 docker）：O-13/O-14 涉及部署形态时，需在有 docker 环境完成构建/运行验证后再宣称支持；
4. **性能基准严谨性**：569MB vs 100MB 约束、压缩率标注需在 O-06 落地后重测并同步约束表述（review-p0 G-05/G-09）。
